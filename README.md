# 한미 테마 신호등

한국·미국 대표 테마 ETF의 일별 종가와 거래량을 수집하여 GitHub Pages에서 자동으로 표시하는 프로젝트입니다. CSV 업로드가 필요 없습니다.

## 1. 설치 (GitHub 웹사이트만 사용)

1. GitHub에서 **New repository**를 눌러 `theme-cycle-radar`라는 **Public** 저장소를 만들고, 기본 브랜치를 `main`으로 설정합니다. (Private 저장소의 Pages 사용 가능 여부는 요금제에 따라 다릅니다.)
2. 이 ZIP을 풀고 **숨김 폴더 `.github`를 포함한 모든 파일과 폴더**를 저장소 루트에 업로드합니다. `site/index.html`, `scripts/update_v4.py`, `.github/workflows/main.yml`, `requirements.txt`가 있어야 합니다.
3. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 변경합니다.
4. 저장소 **Actions → Refresh theme radar and deploy → Run workflow**를 실행합니다.
5. 작업이 성공하면 `https://<사용자명>.github.io/theme-cycle-radar/`에서 확인합니다. 첫 배포까지 몇 분 걸릴 수 있습니다.
6. Actions 탭의 작업 로그에서 `Saved N themes; M errors` 메시지를 확인합니다. 일부 ETF가 실패하면 사이트의 **데이터 수집 오류 및 한계**에도 표시됩니다.

> GitHub Actions의 예약 실행은 지연되거나 생략될 수 있으며, 무료 금융 데이터 제공처의 접속 제한이 발생할 수 있습니다. 매일 정시 업데이트를 보장하지 않습니다.

## 2. 갱신 방식

- `.github/workflows/main.yml`이 평일 **UTC 09:30, 22:30**에 실행됩니다. 한국시간 **18:30, 다음날 07:30**으로 한국·미국 장 마감 후 갱신합니다. 공급자 반영이 늦으면 해당 시간대 신호등은 회색으로 표시될 수 있습니다.
- **Run workflow**로 수동 갱신도 가능합니다.
- 한국 장중에는 평일 UTC 00~06시(한국시간 09~15시) 매 10분 예약 실행합니다. GitHub 예약 실행은 지연·누락될 수 있어 정확한 10분 간격을 보장하지 않습니다.
- 열린 대시보드는 10분마다 배포된 최신 데이터를 다시 읽습니다. 단기 화면이 열려 있으면 단기 데이터도 갱신합니다.
- 브라우저의 **최신 데이터 다시 읽기** 버튼은 이미 배포된 JSON을 다시 불러옵니다. 서버 수집 작업 자체를 실행하지는 않습니다.
- 데이터가 36시간 이상 오래되면 화면에 경고가 표시됩니다. 주말에는 정상적으로 이 경고가 뜰 수 있습니다.

### 현재 ETF 신호등 기준

- 장기 화면은 월·주·일 OHLC를 하이킨 아시로 변환해 HA 종가가 HA 시가보다 높으면 상승으로 판정합니다.
- 방향 일치 점수는 월봉 50점·주봉 30점·일봉 20점입니다. 상승 강도 점수는 HA 시가 대비 상승폭을 각각 5%·3%·1.5%로 정규화해 같은 가중치로 합산합니다.
- 실제 시가 대비 종가 등락률과 HA 방향은 별개입니다. LIT를 포함해 실제 음봉이어도 HA 양봉일 수 있으며 두 수치를 판정 근거에 함께 표시합니다.
- 완료 거래일까지 계산하며 진행 중인 월·주봉은 미확정입니다. 장중 일봉 HA 신호는 제공하지 않습니다. 증권 ETF의 과거 초록 구간은 최근 3년을 조회합니다.
- 단기 화면은 코스피 당일 최저가가 전일 종가 대비 -9% 이하일 때 완료된 5분봉의 반등 조건을 평가합니다.

## 3. 분석 규칙과 해석

**신호:** ETF 종가 기준 전 거래일 대비 **3% 이상 상승**하고 **거래량이 전 거래일의 1.5배 이상**이면 발생합니다. ETF마다 신호를 독립적으로 계산합니다. 해당 일자의 종가가 확정된 뒤에야 신호를 알 수 있습니다.

**점수:** 거래량 강도 30%, 벤치마크 대비 20거래일 상대강도 25%, 가격방향 가중 거래량 대리지표 20%, 테마 확산 **중립값 50** 15%, 최근 10거래일 상승 빈도 10%.

- 한국 벤치마크: `069500.KS` (KODEX 200), 미국: `SPY`.
- 기관/외국인 순매수, 개별 구성종목 동반 상승 데이터는 **제공하지 않습니다**. 따라서 수급·확산을 실제 측정했다고 해석하면 안 됩니다.
- 신호 후 5·20거래일 수익률은 **신호일 종가 기준**이며, 다음날 시가 체결을 가정한 전략 수익률이 아닙니다. 거래비용, 배당 재투자, 세금 및 슬리피지는 제외합니다.
- 가격은 yfinance의 `auto_adjust=True`로 조정된 일별 시세입니다. 공급자 수정에 따라 과거 수치가 바뀔 수 있습니다.
- 종목별 상장 시기·ETF 추종 지수 차이·레버리지 여부가 비교에 영향을 줍니다. 테마 ETF가 테마 전체의 움직임을 완전히 대표하지는 않습니다.
- 점수 임계값(75/60/40)은 실험적이며 검증된 예측 정확도를 의미하지 않습니다.
- ETF 상장폐지나 티커 변경이 있으면 `scripts/update.py`의 `THEMES`를 수정하세요.

## 4. 로컬 테스트

Python 3.11 이상 환경에서:

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
node --test tests/test_dashboard.cjs
python scripts/update_v4.py
python scripts/validate_site.py
python -m http.server 8000 --directory site
```

브라우저에서 `http://localhost:8000`을 열어 확인합니다. 단순히 `site/index.html`을 파일로 직접 열면 일부 브라우저에서 JSON fetch가 차단될 수 있습니다.

## 5. 데이터 실패 시

- **전체 수집 실패:** workflow가 실패하며 신규 사이트 배포를 중단합니다. 기존 Pages 사이트가 있다면 마지막 성공 배포본이 남습니다. 화면의 생성 시각을 확인하세요.
- **일부 수집 실패:** 성공한 ETF만 표시하고 실패한 티커 및 원인을 오류 영역에 표시합니다.
- **실패 원인:** Yahoo Finance 접속 제한, 한국 ETF 심볼 변경, 휴장일, API 응답 오류 등. Actions 로그를 확인하고 재실행하세요.
- 데이터 공급자 이용 약관 및 호출 제한을 확인하고 개인 연구용으로 사용하세요.

## 6. 파일 구조

```
.github/workflows/main.yml    자동 수집 및 GitHub Pages 배포
scripts/update.py             ETF 수집, 점수, 신호 계산
site/index.html               대시보드 UI
site/data.json                실행 시 생성 (처음에는 없음)
tests/test_update.py          단위 테스트
requirements.txt              Python 패키지
```

**주의:** 이 프로젝트는 시장 관찰용 시제품입니다. 1년간 전체 테마에 대한 검증된 정확도 수치는 아직 제공하지 않습니다.

## 7. MA1 월·주·일 신호등과 상승 점수

현재 화면은 증권 ETF 종합 신호등과 테마별 신호등 상승 점수만 제공합니다. 사이클 위치·강도·전환 이력 및 조기 징후 영역은 표시하지 않습니다. 종합 신호등은 테마 표의 첫 열에 배치합니다.

- **MA1은 가격 자체**입니다. 월봉은 직전 월 마지막 거래일 종가, 주봉은 직전 주 마지막 거래일 종가, 일봉은 전 거래일 종가와 비교합니다. 높으면 상승, 낮으면 하락, 같으면 보합입니다. 5기간 평균이나 추가 이동평균 방향 조건은 사용하지 않습니다.
- 월봉 상승 50점 + 주봉 상승 30점 + 일봉 상승 20점으로 합산합니다. 예: 일봉만 상승하면 20점, 월·일봉 상승이면 70점, 모두 상승하면 100점입니다. 실제 상승 확률이나 매수 비중은 아닙니다.
- 거래소 장 마감 시각과 휴장일은 XKRX/XNYS 달력을 사용합니다. 완료 거래일 판정과 과거 구간에는 그날까지 알 수 있었던 가격만 사용합니다. 첫 불완전 상장 주·월은 직전 완성 기간 종가로 채우지 않습니다.
- `etf_trend.method`는 `MA1`이며 각 시간대에 `ma1`, `previous_ma1`을 기록합니다. `bullish_score`는 0~100점입니다. 데이터 부족이면 `null`이며 0점과 구분합니다.
- 거래소가 실제 개장 중이고 오늘 날짜의 가격이 있으면 `etf_trend.intraday`에 별도 미확정 신호·점수·기준일·관측 시각을 기록합니다. 화면은 이 장중 점수를 우선 표시하며 **장중·미확정**을 명시합니다. 장 시작 전·휴장일·마감 후에는 장중 점수를 만들지 않습니다. 수집 시점의 가격으로 계산하며 실시간 자동 갱신이 아닙니다.
- 장중 가격은 완료 거래일 신호·변경 이력·녹색 유지 수익률·과거 초록 구간을 바꾸지 않습니다. 미래 일자의 데이터는 계산에서 제외합니다. 장 마감 후 확보한 종가부터 완료 이력에 반영합니다.
- 점수의 **판정 근거**를 펼치면 월·주·일 현재가(MA1), 직전 기간 종가와 기준일을 볼 수 있습니다. 주말·휴장일은 가짜 일봉으로 채우지 않습니다.

## 8. 증권 ETF 최근 3년 초록 유지 구간

KODEX 증권(102970.KS)을 별도로 수집해 최상단 패널에 표시합니다. 최근 3년 이력은 MA1 규칙으로 재계산하며 최신 완료 거래일부터 달력상 3년 전 같은 날짜까지 양 끝을 포함합니다. 증권 ETF는 같은 수집기로 5년을 조회하고, 일반 테마는 기존 18개월을 유지합니다.

`securities_etf.etf_trend.green_history`에 `window_start`, `asof`, `complete`, `latest_date`, `latest_run`, `runs`를 기록합니다. 완료 거래일 기준 가장 최근 동시 초록 날짜, 해당 연속 구간의 시작·종료일과 유지 여부를 표시하며 전체 구간은 펼쳐서 확인합니다. 장중 신호와 구별하도록 완료 기준일을 함께 표시합니다.

연속은 거래소 거래일 기준이므로 휴장일은 구간을 끊지 않습니다. 노랑·빨강·회색은 끊으며 단 하루의 초록도 구간입니다. 유지 중인 구간은 최신 완료 거래일까지 표시합니다. 조회 범위와 겹치는 구간의 관찰된 시작일은 3년 이전일 수 있습니다. 모든 조회 거래일 판정이 유효하고 초록이 없으면 **최근 3년간 없음**, 누락이 있으면 **데이터 부족**을 안내합니다.

## 9. 검증과 배포

Python 계산 테스트와 Node 화면 테스트 후 실제 시세를 생성·검증하고 Actions로 Pages에 배포합니다. `site/build.json`에는 게시 커밋과 생성 시각을 기록합니다. 사이클 계산의 기존 JSON 필드는 호환성을 위해 남겨 두지만 화면과 신호등 점수 계산에는 사용하지 않습니다. 공급자 조정주가·달력 수정에 따라 재계산된 과거 값은 달라질 수 있습니다.
